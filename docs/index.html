The Problem

Software uses floating-point arithmetic. 0.1 + 0.2 = 0.30000000000000004. That's like measuring a hydraulic fitting with a rubber ruler — the number changes depending on how you hold it.

FP16 (half-precision float) has 76% precision mismatches for values above 2048. INT8 (integer, saturated) has zero.

The Solution

Specify constraints like GD&T for software. GUARD temp IN [15, 55]

Quick Example

# O-ring compression check # AS568-214: compression must be 15-25% to seal GUARD o_ring_squeeze IN [15, 25] WHERE squeeze = (1 - groove_depth / cross_section) * 100 SEVERITY CRITICAL STANDARD 'AS568' UNIT 'percent' # Compiles to FLUX-C bytecode: PUSH_CONST 15 ; min compression % PUSH_REF squeeze ; calculated value RANGE_CHECK ; pass or fail — no NaN, no Inf HALT # Result: 62.2 billion such checks per second on a laptop GPU # 60 million differential test inputs: zero mismatches
